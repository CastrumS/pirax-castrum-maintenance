**The marker problem:**
- **Tried:** probes on real R2, each in its own unique `test/` root that listed empty afterwards.
- **What happens:** Bun removes a trailing `/` from the key on write, delete and presign. The only workaround, adding a `.` segment, is rejected by R2 as a bad signature (`SignatureDoesNotMatch` / 403).
- **Why I reverted:** I had first let `delete` accept marker keys. But `delete("reports/<id>/")` really sends DELETE `reports/<id>`. That silently leaves the marker in place, or deletes a different object if one has exactly that name.
- **Current state:** store key checking is exactly as reviewed. A marker still makes the prune fail loudly, and `scripts/store-selftest.ts` is unchanged. A first selftest run with markers failed as expected but still cleaned up its root; its artifact is `runs/store-selftest-2026-09-25T15-20-29.208Z.json`.

**Decision for you on the marker part:** I recommend keeping the prune's current fail-loud behaviour and adding a README limitation telling operators to delete such markers with the tool that created them. That would drop the requirement for a real marker test. The alternatives are skipping markers during pruning, which the brief forbids, or hand-writing about 40 lines of signed-request code outside Bun's client. Either needs a revised brief.
